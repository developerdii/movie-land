# Architecture

Unidirectional data flow:
```
components → api.js (axios instance) → TMDB API (https://api.themoviedb.org/3/)
```

## Layers
- **`src/api.js`** — the ONLY network/TMDB seam. A dedicated axios instance (`baseURL`, `Authorization: Bearer ${VITE_TMDB_ACCESS_TOKEN}`) with NProgress interceptors; all TMDB methods are listed in `data-model.md`.
- **`src/components/`**:
  - `AsyncImage` — shared lazy-loaded artwork frame with reserved aspect ratio and movie/person fallback icon.
  - `Navbar` — sticky nav, hosts `SearchBar`.
  - `SearchBar` — light search dropdown with a 250 ms debounced query, Movie/TV/Person tabs with per-type counts, genre (movie/TV) and department (person) tags, per-type cached trending/search results, and keyboard navigation (↑/↓/Enter/Esc). Its footer "Browse all" link opens `/browse/{active tab}` with the search text as `q`. With no search text it shows the popularity lists (`/movie/popular`, `/tv/popular`, `/person/popular`), the same order Browse all opens with, under the heading "Popular now". Person rows there carry their rank (#1, #2, …) instead of a popularity score, since the score is not comparable across people.
  - `Slider` — reusable Bootstrap carousel shell (slots `title` and `card`); props `showIndicators` (dots), `showPosition` ("N / M" badge) and `showArrows` (prev/next controls); emits `slid` (`{ index, total }`); initializes its `Carousel` in `onMounted()` (manual nav only).
  - `SectionHeading` — shared section heading (eyebrow label + display title with a gold accent divider below); uses the "Big Shoulders Display" (title) and "Manrope" (eyebrow) fonts; supports an `actions` slot for heading controls.
  - `PosterCard` — the single shared poster card with three variants (`comingSoon`, `movie` (also TV), `person`); one `<a>` link with an aria-label, media area on top + info band below, blurred info band (comingSoon/movie), photo scrim (person), date chip + countdown, rating + type badge, one role badge at most in grid view (`roles` prop, person filmography: the first role that is not the person's main one, and films with the main role show none; see Credits in `data-model.md`); list view shows every role as pills (`allRoles`), and hover/focus lift + gold ring. No outline or border: the card has a soft shadow only, and its background and the image frame are transparent so no dark fringe shows at a white poster's edge.
  - `MediaSection` — reusable grid/list section (eyebrow + title heading, grid/list view toggle, round pagination); the `kind` prop (`person` | `movie` | `tv`) drives the `PosterCard` variant and the detail route; used by Cast (film/TV details) and Filmography (person details). In `serverPaged` mode (browse page) `items` is one TMDB page and paging goes through the `page` / `totalPages` props and the `update:page` event; `loading` dims the list. The current page number is typed in directly (`round-pagination-jump`) and clamped to the valid range; this works in both modes.
  - `MovieSlider` — renders `Slider` with chunked rows of 6 `PosterCard`s; the `variant` (`comingSoon` | `movie`) and `type` (`movie` | `tv`) props drive the cards and the detail route.
  - `PopularMoviesSlider` — hero slider from `movie/popular`; auto-advances every 5s (pauses on hover, resets on manual nav) with prev/next controls, a progress bar and "up next" thumbnails; shows the backdrop, poster, title, rating, year, genre, overview and action buttons.
  - `UpComing` — wraps `MovieSlider` with upcoming movies from the discover endpoint (see `data-model.md`).
  - `Rating` — renders `vote_average` as `x.x / 10`.
  - `MediaViewer` — full-screen photo viewer. Groups are tabs: Backdrops / Posters / Logos on movie and TV pages, Profile / Photos on person pages. The page backdrop is blurred behind the photo; prev/next, a thumbnail row, Escape and arrow keys work. Clicking the dark area outside the photo closes it.
  - `MediaStrip` — a compact row of up to 6 backdrop thumbnails between the hero and the cast on movie and TV pages. The last tile shows how many more there are. Clicking a tile opens `MediaViewer` at that photo.
  - `utils/images.js` — `imageUrl` (TMDB sizes), `sortImages` (score, then votes), `toViewerItems`.  - Loading on the browse page: while a request runs, `MediaSection` shows `PosterCardSkeleton` placeholders (20, one TMDB page) in grid and list view, and the tabs, filters, chevron and pagination are disabled so a second change cannot race the first. The search field stays enabled on purpose: disabling it would drop focus after every debounced query.
  - `BrowseSearch` — the search field in the top row of the browse page, beside the media type tabs. It keeps a local draft and emits `change` with `{ q }` after 300 ms, on Enter or on its search button. Search is a separate TMDB endpoint, so it is not part of the filter bar.
  - `BrowseFilters` — filter bar below the top row, hidden on the people tab. Four equal columns plus a 44 px collapse column. Row 1: Genre, Year, Country, then Sort by in the fourth column as one joined control (the select and the direction toggle share one border), then the collapse chevron. The chevron opens row 2 in the same four columns, with no divider: Language, Min rating, Max rating, Runtime. The collapse column stays empty in row 2. Below the grid, one chip per active filter on a single line, with "Clear all" on the right; Clear all resets the filters only, not the search text. While a search text is set, the filters are off (TMDB search takes none of them). The search field keeps a local draft and emits `change` with `{ q }` after 300 ms, on Enter or on its search button; the other controls emit partial filter patches. The media type tabs are not in this panel: `BrowseView` renders them above it. The URL stays the source of truth.
- **`src/views/`** — route pages: `Home` (`PopularMoviesSlider` + `UpComing`), `MovieDetails`, `TvDetails`, `PersonDetails`, and `BrowseView` (`/browse/:type`, full-page filterable lists with server-side paging; see Browse in `data-model.md`). Its top row holds the media type tabs and `BrowseSearch`. Detail pages share `.detail-page`, the `.detail-title` page-title style and the `.detail-poster` edge treatment. Film details show Director/Writers fact cards; TV details show Created-by/Writers cards plus air dates and season/episode counts; the person page shows Born/Known-for/Credits fact cards, a clamped biography with "Read more", release-sorted filmography (cast and crew merged, see Credits in `data-model.md`), and a Photos strip of up to 6 tagged photos above the filmography. The strip uses the same viewer as movie and TV pages. Profile photos are not reused as backdrops.
- **`src/utils/`** — pure helpers: `date.js` (`formatDate`, `formatMonth`, `formatDay`, `daysUntil`), `language.js` (`getLanguageName`), `collection.js` (`chunk`, `trimToChunks`, `debounce`), `genres.js` (`getGenreMap` for `PosterCard`, `getGenreList` for the browse genre select), `browse.js` (URL query ⇄ browse filter state, TMDB discover params, sort helpers), and `configuration.js` (language and country lists for the browse filters, cached per session).
- **`src/composables/usePagination.js`** — `usePagination(items, pageSize)` for client-side list pagination (legacy; `MediaSection` now pages internally).
- **`src/components/PaginationControls.vue`** — prev/next + "page X / Y" pagination controls (legacy; superseded by the shared `round-pagination`).

## Rules of thumb
- All TMDB calls go through `src/api.js`; never inline axios/fetch in components.
- Carousel components initialize their own `Carousel` instance in `onMounted()` (don't rely on `data-bs-ride`).
- Navigation uses `useRouter().push({ path, query: { id } })`; the detail page keeps the `?id=` convention.
- Keep date formatting in `src/utils/date.js`.
- Browse state lives in the URL query only. `parseBrowseQuery` reads it, `toBrowseQuery` writes it back, and `BrowseView` derives everything from `route.params` / `route.query`. Don't keep filter state in components.
- The browse page is not linked from the navbar or home. Its entry points are the search "Browse all" link and the genre tags on movie and TV detail pages.
