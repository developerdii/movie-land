# Architecture

Unidirectional data flow:
```
components → api.js (axios instance) → TMDB API (https://api.themoviedb.org/3/)
```

## Layers
- **`src/api.js`** — the ONLY network/TMDB seam. A dedicated axios instance (`baseURL`, `Authorization: Bearer ${VITE_TMDB_ACCESS_TOKEN}`) with NProgress interceptors; all TMDB methods are listed in `data-model.md`.
- **`src/App.vue`** — the navbar and the `router-view` container (`.router-view container-xxl`). The container has no card: every page sits on the page background inside the navbar's gutter. A page that needs a bordered card adds `.page-card` to its own root (the About article, and the header of the movie, TV and person pages). Don't add `container-xxl` to a page root; the container already gives the gutter.
- **`src/components/`**:
  - `AsyncImage` — shared lazy-loaded artwork frame with reserved aspect ratio and movie/person fallback icon.
  - `Navbar` — one 56 px row: the logo (a light and a dark wordmark, shown by theme; the whole logo links to Home), the text links Home (`/`) and Browse (`/browse/movie`), where the active one is white with a gold line along the bottom edge. On the right: the `SearchBar` field, a bookmark icon (`/bookmarks`), `ThemeToggle`, and an info icon that opens About (`/about`). Those are the only links in the bar. No collapse menu. On phones (below 576 px) the logo is cut down to its play tile, and the links and icon buttons shrink so the row fits down to 320 px.
  - `BookmarkButton` — the bookmark toggle (`type`, `id`, `variant` props). On the movie, TV and person pages it is a ribbon: a 44×60 px tab hanging from the top edge of the header card (`.page-card`), top right, with a plus (not saved, neutral grey) or a check (saved, gold, the browse tabs' selected colour). It is positioned on the header card (`position: relative` from `.page-card`), so its top edge is the card's; its right offset is `--card-pad` plus its own inset. On the hero it is the `pill` variant, a button with text, styled by the hero's classes. It only calls the bookmarks store.
  - `ThemeToggle` — the navbar dark mode button (moon/sun, `aria-pressed`). Reads and writes the `movieland-theme` localStorage key through `src/utils/theme.js`; see Dark mode in `coding.md`.
  - `SearchBar` — the navbar field (search icon and the placeholder "Movies, TV &amp; people", 300 px wide; icon only under 992 px). Clicking it, or ⌘K / Ctrl+K anywhere, opens a Spotlight-style panel teleported to `body`: centered on desktop, top-anchored on phones, with a fade and scale-in animation, a blurred backdrop, focus trap, and body scroll lock. Esc clears the query first, then closes. Any route change closes it. Inside the panel: a 250 ms debounced query, Movie/TV/Person tabs with per-type counts, genre (movie/TV) and department (person) tags, per-type cached trending/search results, and keyboard navigation (↑/↓/Enter). Its footer "Browse all" link opens `/browse/{active tab}` with the search text as `q`. With no search text it shows the popularity lists (`/movie/popular`, `/tv/popular`, `/person/popular`), the same order Browse all opens with, under the heading "Popular now". Person rows there carry their rank (#1, #2, …) instead of a popularity score, since the score is not comparable across people.
  - `Slider` — reusable Bootstrap carousel shell (slots `title` and `card`); props `showIndicators` (dots), `showPosition` ("N / M" badge) and `showArrows` (prev/next controls); emits `slid` (`{ index, total }`); initializes its `Carousel` in `onMounted()`. `goTo(index)` moves it from outside (used by the page controls). Bootstrap's touch swipes are off (`touch: false`), so a sideways swipe scrolls the poster row instead.
  - `SectionHeading` — shared section heading (eyebrow label + display title with a gold accent divider below); uses the "Big Shoulders Display" (title) and "Manrope" (eyebrow) fonts; supports an `actions` slot for heading controls.
  - `PosterCard` — the single shared poster card with four variants (`comingSoon`, `movie` (also TV), `person`, and `person-v2`, the home-list person card that is laid out like a title card: photo in the 2:3 frame, name and department below, and a PERSON badge top right, or in Born Today an age chip top left in the date chip's place); one `<a>` link with an aria-label, media area on top + info band below, blurred info band (comingSoon/movie), photo scrim (person), date chip + countdown, rating + type badge, one role badge at most in grid view (`roles` prop, person filmography: the first role that is not the person's main one, and films with the main role show none; see Credits in `data-model.md`); `upcoming` prop: a gold "Upcoming" badge in the rating's corner, the rating is hidden (used by the person filmography); list view shows every role as pills (`allRoles`), and hover/focus lift + gold ring. No outline or border: the card has a soft shadow only, and its background and the image frame are transparent so no dark fringe shows at a white poster's edge.
  - `MediaSection` — reusable grid/list section (eyebrow + title heading, grid/list view toggle, page control); the `kind` prop (`person` | `movie` | `tv`) drives the `PosterCard` variant and the detail route; used by Cast (film/TV details) and Filmography (person details). In `serverPaged` mode (browse page) `items` is one TMDB page and paging goes through the `page` / `totalPages` props and the `update:page` event; `loading` dims the list. Below 768 px the client-paged grid (cast, filmography) swipes sideways (`.cast-grid--row`); server-paged browse results stay a two-column grid. With `numbered-pages` (browse only) the page is `RoundPagination`, where the page number is typed in directly (`round-pagination-jump`) and clamped to the valid range; every other list uses `ProgressPagination`.
  - `MovieSlider` — renders `Slider` with chunked rows of 6 `PosterCard`s (one row per slide; below 768 px the row swipes sideways, about two and a half posters visible); the `variant` (`comingSoon` | `movie`) and `type` (`movie` | `tv`) props drive the cards and the detail route. A card with its own `media_type` (the recently viewed and born today sliders mix films, shows and people) uses that type and link instead, and a person there is a `person-v2` card.
  - `PopularMoviesSlider` — hero slider from `movie/popular`; auto-advances every 5s (pauses on hover, resets on manual nav) with prev/next controls, a progress bar and "up next" thumbnails; shows the backdrop, poster, title, rating, year, genre, overview and action buttons.
  - `UpComing` — wraps `MovieSlider` with upcoming movies from the discover endpoint (see `data-model.md`).
  - `ListSection` — a titled `MovieSlider` for one TMDB list (eyebrow, title, `type` movie/tv, `load` = an api method), with the same heading paging as Coming Soon. It hides itself when the request fails or when TMDB returns fewer than `minItems` titles (6 by default). The home page uses it for the "For you" sections and for Popular Movies, Popular TV Shows and Top Rated Movies.
  - `RecentlyViewed` — the last slider on the home page: the eighteen films, TV shows and people opened most recently (`composables/useRecent.js`), in slides of six with `ProgressPagination`, fetched again from TMDB. Shown from six titles.
  - `BornToday` — the home list above Recently Viewed: the most popular people born today, from the Wikidata and TMDB lookup in `composables/useBornToday.js` (see Born today in `data-model.md`). Slides of six, up to three, with `ProgressPagination`; shown from six people. Its cards are `person-v2`.
  - `Rating` — renders `vote_average` as `x.x / 10`.
  - `ScoreSummary` — the rating block on movie and TV pages (`score`, `votes`, `facts` and `extras` props): a 64 px gold ring with the score, "User score" and the vote count, a divider, then the facts (the first line is emphasised). On phones the facts drop under the ring and the divider is hidden. It replaced the old rating pill and meta row on those pages. `extras` adds sections after the facts, each a list of untitled items stacked one under the other: the US age rating in a box (films and shows, hidden when TMDB has none) and, on shows, the network under it.
  - `MediaViewer` — full-screen photo viewer. Groups are tabs: Backdrops / Posters / Logos on movie and TV pages, Profile / Photos on person pages. The page backdrop is blurred behind the photo; prev/next, a thumbnail row, Escape and arrow keys work. Clicking the dark area outside the photo closes it. Until a photo has loaded, a shimmer skeleton holds its space, sized from the photo's TMDB width/height (kept in `toViewerItems` in `utils/images.js`) and the group's image size, so the photo does not jump when it appears.
  - `MediaStrip` — a compact row of up to 6 backdrop thumbnails between the hero and the cast on movie and TV pages. The last tile shows how many more there are. Clicking a tile opens `MediaViewer` at that photo.
  - `utils/images.js` — `imageUrl` (TMDB sizes), `sortImages` (score, then votes), `toViewerItems`.  - Loading on the browse page: while a request runs, `MediaSection` shows `PosterCardSkeleton` placeholders (20, one TMDB page) in grid and list view, and the tabs, filters, chevron and pagination are disabled so a second change cannot race the first. The search field stays enabled on purpose: disabling it would drop focus after every debounced query.
  - `BrowseSearch` — the search field in the top row of the browse page, beside the media type tabs. It keeps a local draft and emits `change` with `{ q }` after 300 ms, on Enter or on its search button. Search is a separate TMDB endpoint, so it is not part of the filter bar.
  - `BrowseFilters` — filter bar below the top row, hidden on the people tab. Four equal columns plus a 44 px collapse column. Row 1: Genre, Year, Country, then Sort by in the fourth column as one joined box (one 12 px border around the select and the direction toggle, divided by a single line), then the collapse chevron. The chevron opens row 2 in the same four columns, with no divider: Language, Min rating, Max rating, Runtime. The collapse column stays empty in row 2. Row 3 holds Min votes and Max votes side by side (one column each, like the rating pair above); the pair spans two columns so it starts a new row and skips the collapse column. Below the grid, one chip per active filter on a single line, with "Clear all" on the right; Clear all resets the filters only, not the search text. While a search text is set, the filters are off (TMDB search takes none of them). The search field keeps a local draft and emits `change` with `{ q }` after 300 ms, on Enter or on its search button; the other controls emit partial filter patches. The media type tabs are not in this panel: `BrowseView` renders them above it. The URL stays the source of truth.
- **`src/views/`** — route pages: `Home` (`PopularMoviesSlider` hero, then `UpComing`, then three `ListSection`s: Popular Movies, Popular TV Shows, Top Rated Movies, then `BornToday`, and last `RecentlyViewed`), `MovieDetails`, `TvDetails`, `PersonDetails`, `About` (`/about`: plain page with our own text about the project and the TMDB credit; its route has `meta: { compactCard: true }`, so `App.vue` adds `.router-view--compact` (on desktop the column is 744 px wide and centered, which is the 720 px card plus the gutter); the article itself is a `.page-card`), `BookmarksView` (`/bookmarks/:type`: the saved titles in the browse layout, with tabs and counts, grid or list, 20 per page; see Bookmarks in `data-model.md`), and `BrowseView` (`/browse/:type`, full-page filterable lists with server-side paging; see Browse in `data-model.md`). Browse and bookmarks share the list-page styles in `app.scss` (`.browse-top`, `.browse-seg`, `.browse-page .cast-grid`), so a page's own style block is not needed for them. Its top row holds the media type tabs and `BrowseSearch`. Detail pages share `.detail-page`, the `.detail-title` page-title style and the `.detail-poster` edge treatment. On the movie, TV and person pages the hero (and the person header) and the Photos strip sit in one `.page-card`; the cast, filmography and recommendations sit outside it on the page background, like the home sections below the hero. Under the title, movie and TV pages show the original title in `.detail-original-title` (small and muted) when it differs from the displayed title. Film details show Director/Writers fact cards; TV details show Created-by/Writers cards plus air dates and season/episode counts; the person page shows Born/Known-for/Credits fact cards, a clamped biography with "Read more", release-sorted filmography (cast and crew merged, see Credits in `data-model.md`), and a Photos strip of up to 6 tagged photos above the filmography. The strip uses the same viewer as movie and TV pages. Profile photos are not reused as backdrops. Below 768 px the film, TV and person headers all put the poster beside the title block (5 to 7 columns), and the title scales down to fit.
- **`src/utils/`** — pure helpers: `date.js` (`formatDate`, `formatMonth`, `formatDay`, `daysUntil`), `language.js` (`getLanguageName`), `collection.js` (`chunk`, `trimToChunks`, `debounce`), `genres.js` (`getGenreMap` for `PosterCard`, `getGenreList` for the browse genre select), `browse.js` (URL query ⇄ browse filter state, TMDB discover params, sort helpers), and `configuration.js` (language and country lists for the browse filters, cached per session).
- **`src/components/RoundPagination.vue`** — the browse page's page switcher for its server-paged results, which can run to 500 pages: round prev/next buttons, and a pill with the typed page number and the total ("n of N"). `MediaSection` uses it only with `numbered-pages`. It emits `update:page` (1-based); the parent decides what a page change does.
- **`src/components/ProgressPagination.vue`** — the page control for every list except browse: the hero's "Up next" control, with round prev/next arrows, the current page number, a thin gold track filled up to the current page, and the total. The track is the shared `ProgressTrack`. The arrows and the track both go through `requestPage`, which sends one page change at a time (see below), so a drag moves the carousel page by page as the pointer crosses each one. Used by the carousel headings (Coming Soon, the home lists, the recommendations, Recently Viewed, Born Today), the cast and filmography in `MediaSection`, and the bookmark results. Carousels expose `goTo(index)` (`Slider` → `MovieSlider`), so the control can move them. It emits `update:page` (1-based); the parent decides what a page change does.
- **`src/components/ProgressTrack.vue`** — the shared track of the progress controls: a thin line filled up to the current page, with a taller hit area. A click moves to the page under the pointer, a drag moves through the pages as the pointer crosses them, and the arrow, Home and End keys work when it has focus. It only reports the page it wants (`change`), so a parent that moves in steps can keep up with the pointer. The knob and the thicker line show only on hover or focus. Its colours can be set with `--progress-line`, `--progress-fill` and `--progress-ring`. Used by `ProgressPagination` and by the hero's Up Next track (`PopularMoviesSlider`), which sets the slide directly.

## Rules of thumb
- All TMDB calls go through `src/api.js`; never inline axios/fetch in components.
- Carousel components initialize their own `Carousel` instance in `onMounted()` (don't rely on `data-bs-ride`).
- Navigation uses `useRouter().push({ path, query: { id } })`; the detail page keeps the `?id=` convention.
- Keep date formatting in `src/utils/date.js`.
- Browse state lives in the URL query only. `parseBrowseQuery` reads it, `toBrowseQuery` writes it back, and `BrowseView` derives everything from `route.params` / `route.query`. Don't keep filter state in components.
- The browse pages are reached from the navbar Browse button, the search "Browse all" link, and the genre tags on movie and TV detail pages. The home page does not link to them.
